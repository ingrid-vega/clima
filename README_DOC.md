## 📁 Carpetas Principales

### 1. **`src/app/` - App Router (Next.js)**

Next.js usa una estructura de carpetas basada en rutas. Cada carpeta puede contener un archivo especial:
- `page.js`: Componente que se renderiza en esa ruta.
- `layout.js`: Layout que envuelve las páginas.
- `api/[ruta]/route.js`: Endpoints HTTP.

#### `src/app/page.js` - Página Principal

**¿Qué hace?**
- Es el componente principal de la app (ruta `/`).
- Contiene el formulario para buscar ciudades y mostrar el clima.
- Maneja la lógica de cliente (interactividad, estado).

**Características clave:**
```javascript
"use client"  // Indica que es componente cliente (usa React hooks)
```

**Estado que maneja:**
- `input`: Texto que escribe el usuario (ciudad a buscar).
- `city`: Ciudad seleccionada para mostrar.
- `weather`: Objeto con datos de clima (temperatura, humedad, emoji, etc.).
- `loading`: Si está cargando datos.
- `error`: Mensaje de error si algo falla.
- `useRealApi`: Si usar API real (OpenWeatherMap) o datos mock.

**Funciones principales:**

1. **`fetchWeatherForCity(city)`**
   - Intenta obtener datos llamando a `/api/weather?q={ciudad}` (proxy server-side).
   - Si falla, usa el fallback: `public/data/weather.json`.
   - Busca la ciudad en el JSON mock y la devuelve.

2. **`useEffect` inicial (al montar)**
   - Comprueba si el servidor tiene API key configurada (`/api/config`).
   - Carga datos iniciales de "Viña del Mar".

3. **`handleSubmit(e)`**
   - Maneja el envío del formulario.
   - Busca la ciudad usando `fetchWeatherForCity()`.
   - Actualiza el estado con los datos o error.

**Interfaz (UI):**
- Header con título "Clima".
- Formulario con:
  - Input de texto para el nombre de la ciudad.
  - Checkbox para elegir API real o mock.
  - Botón de búsqueda.
- Sección de resultados:
  - Emoji del clima (☀️, 🌧️, ⛅, etc.).
  - Temperatura en °C.
  - Descripción (soleado, nublado, etc.).
  - Tabla con humedad, viento, presión, sensación térmica.
- Footer con créditos.

**Tecnología:**
- React (`useState`, `useEffect` para estado y ciclo de vida).
- Tailwind CSS para estilos (clases de utilidad como `bg-blue-100`, `text-3xl`, etc.).
- `fetch` para llamadas HTTP.
- Atributos de accesibilidad (`aria-label`, `aria-live="polite"`).

### 2. **`src/app/api/` - Endpoints Server-Side**

Cada carpeta dentro de `api/` con un archivo `route.js` define un endpoint HTTP.

#### `src/app/api/weather/route.js` - Proxy a OpenWeatherMap

**Ruta:** `GET /api/weather?q={ciudad}`

**¿Qué hace?**
- Actúa como proxy/intermediario entre el cliente y la API de OpenWeatherMap.
- Valida que existe la clave API en `process.env.OPENWEATHER_API_KEY`.
- Llama a OpenWeatherMap con la ciudad.
- Transforma la respuesta a un formato simple.

**Flujo:**
```
Cliente                    Tu Servidor              OpenWeatherMap
(page.js)      →      (weather/route.js)     →     API
                       (valida clave, llama,
                        transforma respuesta)
```

**Datos que devuelve:**
```json
{
  "city": "Viña del Mar",
  "country": "CL",
  "temp": "22°C",
  "feels_like": "21°C",
  "humidity": "60%",
  "pressure": "1015 hPa",
  "wind": "15 km/h",
  "desc": "soleado",
  "emoji": "☀️"
}
```

**Manejo de errores:**
- Si no tiene API key → responde `500` con mensaje "API key not configured".
- Si OpenWeatherMap devuelve `404` (ciudad no encontrada) → responde `404`.
- Otros errores → responde con código y detalles del upstream.

---

#### `src/app/api/config/route.js` - Info de Configuración

**Ruta:** `GET /api/config`

**¿Qué hace?**
- Devuelve si el servidor tiene la API key de OpenWeatherMap configurada.
- Permite que el cliente sepa si puede usar la API real o debe usar mock.

**Respuesta:**
```json
{
  "hasApiKey": true  // o false
}
```

**Uso en `page.js`:**
```javascript
const conf = await fetch('/api/config');
const json = await conf.json();
setServerHasKey(!!json.hasApiKey);  // Usuario puede elegir usar API real
```

---

#### `src/app/api/history/route.js` - Historial de Búsquedas

**Rutas:**
- `POST /api/history` - Guarda una búsqueda en la BD.
- `GET /api/history` - Obtiene el historial.

**¿Qué hace?**
- Persiste las búsquedas del usuario en una base de datos Postgres.
- Permite recuperar el historial de ciudades consultadas.

**Datos guardados:**
```json
{
  "id": 1,
  "city": "Viña del Mar",
  "searched_at": "2025-12-08T15:30:00Z"
}
```

**Uso en `page.js` (opcional):**
```javascript
// Guardar búsqueda
await fetch('/api/history', {
  method: 'POST',
  body: JSON.stringify({ city: 'Santiago' })
});

// Leer historial
const hist = await fetch('/api/history');
const searches = await hist.json();
```

#### `src/app/api/health/route.js` - Health Check

**Ruta:** `GET /api/health`

**¿Qué hace?**
- Devuelve un estado simple indicando que la app está en línea.
- Útil para monitoreo y verificar que el servidor está vivo.

**Respuesta:**
```json
{
  "ok": true
}
```

### 3. **`src/lib/` - Helpers y Utilidades**

#### `src/lib/db.js` - Conexión a Base de Datos

**¿Qué hace?**
- Centraliza la lógica de conexión a Postgres.
- Proporciona funciones helper para guardar/leer historial.

**Ejemplo de contenido:**
```javascript
import { Pool } from 'pg';

const pool = new Pool({
  connectionString: process.env.DATABASE_URL
});

export async function saveSearch(city) {
  const query = 'INSERT INTO searches (city) VALUES ($1)';
  await pool.query(query, [city]);
}

export async function getHistory() {
  const query = 'SELECT * FROM searches ORDER BY searched_at DESC';
  const res = await pool.query(query);
  return res.rows;
}
```

**Uso en `api/history/route.js`:**
```javascript
import { saveSearch, getHistory } from '@/lib/db';

export async function POST(req) {
  const { city } = await req.json();
  await saveSearch(city);
  return NextResponse.json({ ok: true });
}
```

### `jsconfig.json` - Alias de Rutas

**¿Qué es?**
- Permite usar imports cortos con alias `@/`.

**Ejemplo:**
```javascript
// Sin alias (ruta larga)
import { saveSearch } from '../../../lib/db';

// Con alias (ruta corta)
import { saveSearch } from '@/lib/db';
```

**Configuración:**
```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]  // @/ apunta a src/
    }
  }
}
```

## 🔄 Flujo de Datos (User Journey)

### 1️⃣ Usuario abre la app
```
1. Navegador abre http://localhost:3000
2. Next.js renderiza page.js
3. useEffect inicial:
   - Llama a /api/config → sabe si hay API key
   - Llama a /api/weather?q=Viña%20del%20Mar → carga clima inicial
   - Muestra datos en pantalla
```

### 2️⃣ Usuario escribe una ciudad y busca
```
1. Usuario escribe "Santiago" en el input
2. Usuario hace click en "Buscar"
3. handleSubmit():
   - Si useRealApi=true:
     a. Llama a /api/weather?q=Santiago
     b. Servidor llama a OpenWeatherMap
     c. Devuelve JSON con clima
   - Si useRealApi=false:
     a. Lee public/data/weather.json
     b. Busca "Santiago" en el array
     c. Devuelve datos mock
4. page.js muestra resultados
5. (Opcional) Guarda búsqueda en /api/history → Postgres
```

### 3️⃣ Error: ciudad no encontrada
```
1. Usuario busca "Xyz" (no existe)
2. /api/weather?q=Xyz devuelve 404
3. page.js cae al fallback (weather.json)
4. "Xyz" no está en el mock
5. Muestra primera ciudad del mock como default
```
